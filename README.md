Задание 1 - Выбранный шаблон проектирования: Фабрика
  Этот метод позволяет создавать объекты (плагины) без жёсткой привязки к
  конкретным классам, используя интерфейс IPlugin.
  Метод LoadPlugins загружает плагины через рефлексию, позволяя добавлять
  новые .dll без изменения основного кода.
  Фабрика скрывает сложность создания объектов, предоставляя единый
  интерфейс для работы с плагинами. Это упрощает поддержку и расширение
  функционала приложения.
  Основное приложение взаимодействует только с интерфейсом IPlugin, а
  конкретные реализации подгружаются автоматически. Это снижает
  зависимость от конкретных классов и упрощает внедрение новых плагинов.
Задание 2 - Выбранный шаблон проектирования: Цепочка обязанностей
  Шаблон Chain of Responsibility подходит для этой задачи, потому что:
  • Каждый обработчик может выполнять свою задачу независимо от
  других.
  • Легко добавлять новые этапы обработки данных без изменения
  существующих компонентов.
  • Поддерживает обработку данных через несколько этапов, что делает
  систему расширяемой.
  • Можно легко контролировать, когда и как завершить обработку
  (например, если данные не прошли одну из проверок).
Задание 3 - Выбранный шаблон проектирования: Proxy
  Шаблон Proxy подходит для кэширования, потому что:
  1. Перехватывает запросы к основному источнику данных.
  2. Уменьшает нагрузку на основной источник, проверяя наличие данных
  в кэше перед их запросом.
  3. Абстрагирует кэш от основной логики работы с данными.
  4. Позволяет легко внедрять стратегии очистки кэша (например, срок
  жизни данных, ограничение по размеру).
